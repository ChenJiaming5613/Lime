# 自动化脚本

引擎运行时会在本地回环接口上提供 HTTP 服务，外部脚本可以读写 Pass 参数、开关面板、截图。这既是自动化测试的手段，也是开发时替代反复手点界面的调试手段。

命令与参数的完整清单见 [05-自动化能力参考.md](05-自动化能力参考.md)，本文讲怎么写。

## 为什么可靠

两个性质决定了它能用来做断言，值得先理解：

**命令在帧与帧之间的主线程上执行。** 网络线程只负责解析和入队，真正执行发生在主循环里。所以处理函数看到的状态一定是一致的，而且一次修改会体现在**紧随其后的那一帧**画面里。

**截图是从 GPU 纹理读回，不是抓屏。** 因此不受窗口遮挡、层级顺序、DPI 缩放影响，窗口在后台也能截。

两者合起来的结果是：**把一个 Pass 暂停，连续两次截图的字节完全一致**。所以可以直接用 PNG 字节比较作为断言。

```python
engine.set_pass_values("Quad", {"RotationSpeed": 0.0})
engine.wait_frames(2)
first = engine.screenshot(source="viewport")
engine.wait_frames(2)
assert engine.screenshot(source="viewport") == first
```

## 两种写法，用途不同

| | 项目脚本 | pytest 测试 |
| --- | --- | --- |
| 位置 | `Projects/<项目>/Automation/*.py` | `Automation/tests/test_*.py` |
| 用途 | 复现场景、手动验证、调试 | 回归覆盖，随 `ctest` 跑 |
| 入口 | `def run(engine)` | `def test_xxx(engine)` |
| 依赖 | 无（只用标准库） | 需要 pytest |
| 运行 | `Automation.ps1 run <名字>` | `Automation.ps1 test` |

日常调试写项目脚本；要防止功能回退写 pytest。

## 项目脚本

### 目录与入口

放在 `Projects/<项目名>/Automation/` 下，每个文件暴露一个 `run(engine)`，不需要注册：

```python
# Projects/MyGame/Automation/quad.py
"""验证四边形渲染以及反射参数生效。"""

from __future__ import annotations

from pathlib import Path

# 截图放到引擎的输出目录，不要污染源码树
OUTPUT_DIR = Path("Saved") / "Automation"


def run(engine) -> dict:
    quad = engine.find_pass()
    assert quad is not None, "四边形 Pass 未注册"

    fields = {field["name"] for field in engine.describe_pass(quad)}
    assert {"bVisible", "Scale", "Color"} <= fields, f"字段不符预期: {sorted(fields)}"

    original = engine.get_pass_values(quad)

    # 冻结旋转让渲染确定，这样截图才可比较
    engine.set_pass_values(quad, {"RotationSpeed": 0.0})
    engine.wait_frames(2)
    first = engine.screenshot(source="viewport")
    engine.wait_frames(2)
    assert engine.screenshot(source="viewport") == first, "冻结后画面仍在变化"

    engine.set_pass_values(quad, {"Color": [0.2, 0.9, 0.4, 1.0]})
    engine.wait_frames(2)
    assert engine.screenshot(source="viewport") != first, "改 Color 没有改变画面"

    # 隐藏必须真的停止绘制
    engine.set_pass_values(quad, {"bVisible": False})
    engine.wait_frames(2)
    assert engine.screenshot(source="viewport") != first, "隐藏后画面没变"

    # 还原，这样 --attach 到活动实例时不会留下副作用
    engine.set_pass_values(quad, original)
    engine.wait_frames(2)

    destination = engine.save_screenshot(OUTPUT_DIR / "quad.png", source="viewport")
    assert not engine.errors(), f"引擎记录了错误: {engine.errors()}"
    return {"artifacts": [destination], "pass": quad}
```

### 约定

| 约定 | 说明 |
| --- | --- |
| 文件名 | 即脚本名（`quad.py` → `quad`），查找时大小写无关 |
| 首行 docstring | `list` 命令显示的描述，请务必写 |
| `_` 开头的文件 | 视为私有辅助模块，不会被列为可运行脚本 |
| 抛 `AssertionError` | 脚本失败，`assert` 就是自然的写法 |
| 返回 `False` | 也算失败，不用抛异常 |
| 返回 `{"artifacts": [...]}` | 汇报产出的文件，会打印在结果里 |

脚本可以 `import` 同目录下的辅助模块 —— 运行器会临时把脚本目录加进 `sys.path`。

### 运行

```powershell
./Scripts/Automation.ps1 list -Project MyGame            # 列出脚本
./Scripts/Automation.ps1 run quad -Project MyGame        # 起引擎跑，跑完关掉
./Scripts/Automation.ps1 run -Project MyGame             # 不指定名字则全部跑
./Scripts/Automation.ps1 run quad -Backend vulkan        # 指定后端
```

输出：

```
Launched MyGame on D3D12 (NVIDIA GeForce RTX 3080)

=== summary ===
  [PASS] quad
         -> Saved\Automation\quad.png

All 1 script(s) passed.
```

失败时会打印断言消息和完整 traceback，并且**继续跑后面的脚本**，不会中断在第一个失败上。

### 调试循环：--attach

这是这套东西最实用的地方。加 `--attach` 后不再新起进程，而是连到**已经在跑的引擎**，跑完窗口也不关：

```powershell
# 终端 1：手动起一个引擎，窗口保持打开
./Build/ninja/Bin/Debug/MyGame/MyGame.exe

# 终端 2：反复改脚本、反复跑，观察窗口里的变化
./Scripts/Automation.ps1 run quad -Project MyGame -Remaining --attach
```

引擎启动要几秒，`--attach` 省掉了每次迭代的这个开销。

### 交互式 shell

想探索而不是写死脚本：

```powershell
./Scripts/Automation.ps1 shell -Project MyGame
./Scripts/Automation.ps1 shell -Project MyGame -Remaining --attach
```


## pytest 测试

### 位置与 fixture

放在 `Automation/tests/test_*.py`。可用的 fixture：

| fixture | 作用域 | 说明 |
| --- | --- | --- |
| `engine` | 函数 | 已连接的 `LimeClient`，进入时清空日志 |
| `session` | 模块 | 底层的 `LimeSession`，需要进程信息时用 |
| `triangle_pass` | 函数 | 项目的反射 Pass 名，**退出时自动还原参数** |
| `headless_engine` | 函数 | `--no-editor` 的引擎，测试纯运行时路径 |
| `artifacts` | 函数 | 每个测试独立的临时目录，用于存截图 |
| `backend` | 模块 | 当前后端，由 `--backend` 参数化 |

```python
def test_color_changes_the_render(engine, triangle_pass):
    engine.set_pass_values(triangle_pass, {"RotationSpeed": 0.0})
    engine.wait_frames(2)
    before = engine.screenshot(source="viewport")

    engine.set_pass_values(triangle_pass, {"Color": [0.0, 1.0, 0.0, 1.0]})
    engine.wait_frames(2)
    assert engine.screenshot(source="viewport") != before
```

### 一个重要约束

**引擎进程按「模块 + 后端」共享。** 启动一次要几秒，每个测试单独起一个太浪费。代价是：**测试必须把引擎还原成它拿到时的状态**。

`triangle_pass` fixture 正是为此存在 —— 它记下参数，测试结束自动写回。自己改了别的状态（面板可见性、窗口标题），要自己用 `try/finally` 还原：

```python
def test_panel_toggles(engine):
    original = engine.panel_visible("Console")
    try:
        engine.show_panel("Console", visible=False)
        assert engine.panel_visible("Console") is False
    finally:
        engine.show_panel("Console", visible=original)
```

另外，`engine` fixture 在退出时会检查引擎有没有记录 error 级日志 —— **断言全过但引擎报错了，测试照样算失败**。

### 运行

```powershell
./Scripts/Automation.ps1 test                          # D3D12
./Scripts/Automation.ps1 test -Backend d3d12,vulkan    # 双后端矩阵
```

或者直接用 pytest，参数更灵活：

```powershell
cd Automation
python -m pytest -q                       # 全部
python -m pytest -q -k screenshot         # 只跑名字含 screenshot 的
python -m pytest -q -m "not slow"         # 跳过会另起引擎的测试
python -m pytest -q --backend vulkan
python -m pytest -x -vv                   # 第一个失败就停，详细输出
```

### 接入 ctest

pytest 套件已注册进 ctest，按后端各一个测试项：

```powershell
ctest --test-dir Build/ninja -C Debug                  # C++ 与 Python 全跑
ctest --test-dir Build/ninja -C Debug -L automation    # 只跑自动化
```

pytest 没安装时会打印一行 status 跳过，不会让构建失败。安装依赖：

```powershell
python -m pip install -r Automation/requirements.txt
```

## 直接用 Python 库

不走脚本和 pytest，自己写程序：

```python
import sys
sys.path.insert(0, "Automation")          # 从仓库根目录运行时

from lime_automation import LimeSession, find_engine

# 方式一：自己起一个引擎，退出时自动关掉
with LimeSession(project="MyGame", backend="vulkan", width=1280, height=720) as engine:
    engine.set_pass_values("Quad", {"Scale": 2.0})
    engine.save_screenshot("shot.png", source="viewport")

# 方式二：连到已在运行的引擎，不影响它的生命周期
engine = find_engine(project="MyGame").connect()
print(engine.engine_stats())
```

`LimeSession` 默认用 `port=0`（系统分配端口），所以**多个会话可以并行**，互不干扰：

```python
with LimeSession(backend="d3d12") as a, LimeSession(backend="vulkan") as b:
    assert a.engine_info()["backend"] != b.engine_info()["backend"]
```

`LimeSession` 还会在启动前删掉 `Saved/EditorLayout.ini` —— 否则用户保存的旧布局会把新增面板藏起来，测试就看不到它。不想这样传 `keep_layout=True`。

## 实用技巧

### 让断言自解释

`pass.describe` 会返回字段的类型、范围、提示，所以合法值可以**问引擎**而不是写死：

```python
speed = next(f for f in engine.describe_pass("Quad") if f["name"] == "Scale")
engine.set_pass_values("Quad", {"Scale": speed["max"]})     # 用上界，不硬编码 3.0
```

这样以后改了 `Range(0.1f, 3.0f)`，脚本不需要跟着改。

### 不硬编码 Pass 名

```python
quad = engine.find_pass()        # 第一个有反射设置、且非引擎自带的 Pass
```

### 批量命令减少往返

一次连改多个值时，`batch` 只付一次网络开销（每条命令仍在主线程逐个执行）：

```python
replies = engine.batch([
    ("pass.set", {"pass": "Quad", "values": {"Scale": 2.0}}),
    ("panel.show", {"panel": "Console", "visible": False}),
    "engine.stats",
])
assert all(r.ok for r in replies)
```

### 从 PNG 字节读尺寸

不用装图像库：

```python
import struct

def png_size(data: bytes) -> tuple[int, int]:
    assert data.startswith(b"\x89PNG\r\n\x1a\n")
    return struct.unpack(">II", data[16:24])
```

### 判断画面非空

空白帧压缩后很小，文件大小就是够用的信号：

```python
assert len(engine.screenshot()) > 5000, "画面看起来是空的"
```

### 两种截图来源

| 来源 | 内容 |
| --- | --- |
| `backBuffer`（默认） | 整个窗口，含编辑器 UI |
| `viewport` | 仅场景，不含编辑器边框；`--no-editor` 时不存在 |

验证渲染用 `viewport`（不受面板布局影响），验证 UI 用 `backBuffer`。

## 常见问题

**`EngineNotFoundError`**
没有在跑的引擎。用 `--attach` 前要先手动启动一个，或者去掉 `--attach` 让脚本自己起。

**改了值但截图没变**
`wait_frames()` 漏了。命令在帧间执行，需要至少一帧才能体现到画面。

**两次截图应该相同却不同**
有动画还在跑。把相关的 `RotationSpeed` 设为 0 或 `bPaused` 设为 true。

**`CommandError: Unknown field 'xxx'`**
字段名要用 C++ 里的**变量名**，不是 `FProp()` 里的显示名。用 `describe_pass()` 确认。

**pytest 报 fixture 找不到**
`conftest.py` 在 `Automation/tests/` 下，要在 `Automation/` 目录里运行 pytest。

**测试单独跑通过、一起跑失败**
共享引擎的状态污染。检查是否有测试改了状态没还原。

**`viewport` 截图报错**
引擎以 `--no-editor` 启动，没有离屏目标。改用 `backBuffer`。
